# gmail-label-archiver

Gmail の指定ラベルが付いたスレッドを、ラベルごとに設定した保持日数を超えたら受信トレイから自動でアーカイブする Google Apps Script (GAS) ツールです。アーカイブ対象・保持日数は Google スプレッドシートで管理し、日次トリガーで無人運用できます。

## 特徴

- **ラベル単位の保持期間管理** — 「このラベルは 30 日、別のラベルは 7 日」といったルールをスプレッドシートで宣言的に設定。
- **ラベル一覧の自動同期とチェックボックス選択** — Gmail の全ユーザーラベルが設定シートに自動で並び、アーカイブしたいラベルの `対象` にチェックを入れて保持日数を書くだけ。ラベル名の手入力や誤記によるルール不発が無い。
- **親ラベル指定で配下も対象** — 親ラベル（例: `仕事`）を対象にすると、配下の子孫ラベル（`仕事/案件A`、`仕事/案件A/議事録` など）にも同じ保持日数を自動適用。実際に効く日数はシートの `適用日数` 列で確認できる。
- **非破壊なアーカイブのみ** — 受信トレイから外す（標準アーカイブ）だけ。削除・ゴミ箱移動・既読変更・他ラベルの変更は一切行いません。
- **スター付き・新着を保護** — スター付きスレッド、保持日数を超えていないスレッドは対象外。
- **権威的な再判定** — Gmail 検索の近似フィルタに頼らず、最新メッセージ日時とスター有無をコード側で再判定してからアーカイブ。
- **実行予算と持ち越し** — 1 回の実行で処理する上限（既定 300 件）を超えた分は受信トレイに残し、次回実行へ持ち越し。予算はルール間で公平に配分されるため、滞留の多いラベルが他のラベルを締め出さない。
- **冪等な日次トリガー** — セットアップを何度実行してもトリガーは常に 1 件。
- **自動デプロイ** — `main` への push でテスト通過を条件に GitHub Actions が GAS へ同期。

## 仕組み

日次トリガー（または手動実行）で `archiveLabeledThreads` が呼ばれ、以下を実行します。

1. **ラベル一覧の同期** — Gmail の全ユーザーラベルを設定シートへ同期する（未登録ラベルの追記・`適用日数`/`状態` 列の更新。旧形式シートなら初回のみ新形式へ移行）。詳しくは「[ラベル一覧の同期](#ラベル一覧の同期)」を参照。同期だけが失敗した場合はログに記録し、その時点のシート内容でアーカイブを続行する（実行は最後にエラーとして終了）。
2. **設定読取** — Script Property が指すスプレッドシートを読み、`対象` にチェックがあり `保持日数` が正の整数の行を明示ルール（ラベル名・保持日数）として取得。チェックありで保持日数が無効な行はラベルごとにログしてスキップ。構成不備（ID 未設定・シート不在・`ラベル名`/`保持日数` ヘッダの欠落）はログに記録したうえで例外として終了（トリガー失敗通知メールが届く）。明示ルールが 0 件なら何もせず終了。
3. **親ラベルの展開** — Gmail の全ユーザーラベルを取得し、各ルールのラベル名を親とみなして配下の子孫ラベルへ保持日数を継承したルールを追加。子孫に明示ルールがあればそちらを優先し、複数の祖先がある場合は最も近い（最長一致の）親を採用。ラベル名の照合は大文字小文字を区別しない（Gmail と同じ）。
4. **ルールごとに処理** — 各ラベルについて `label:"<ラベル名>" in:inbox -is:starred older_than:<保持日数>d` で候補を検索。検索条件はメッセージ単位で効くため（最近の返信があるスレッド等もヒットする）、`ARCHIVE_SEARCH_LIMIT` 件ずつページングし、1 ルールあたり最大 `ARCHIVE_SCAN_LIMIT_PER_RULE` 件まで走査する。
5. **権威的再判定** — 候補のうち「最新メッセージが保持日数を厳密に超える」かつ「スター無し」のスレッドだけを確定対象にする。親子両方のラベルが付いたスレッドなど、複数ルールにヒットするスレッドは 1 回の実行内で 1 回だけ処理・計数する。
6. **バッチアーカイブ** — 確定対象を 100 件単位で `moveThreadsToArchive`。実行全体の予算をルール間で公平に配分（各ルールに「残予算 ÷ 残ルール数」を割当て、使い残しは後続ルールへ、割当を使い切ったルールには 2 巡目で残りを配分）し、超過分は次回へ持ち越し。
7. **サマリ出力** — 処理ルール数・ルール別件数・エラー数・残予算を実行ログへ出力。ルール単位のエラーは記録のうえ次のルールへ継続し、ルール単位のエラーが 1 件以上ある場合や手順 1 の同期が失敗していた場合は、サマリ出力後に例外として終了（トリガー失敗通知メールで気づける）。

## 設定スプレッドシート

1 行目をヘッダ、2 行目以降をデータ行として読みます。シートには Gmail の全ユーザーラベルがシステムによって自動で並ぶので、利用者はアーカイブしたいラベルの `対象` にチェックを入れ、`保持日数` を書くだけです（ラベル名を手で入力する必要はありません）。

| 対象 | ラベル名 | 保持日数 | 適用日数 | 状態 |
|---|---|---|---|---|
| ☑ | アーカイブ | 30 | 30 | |
| ☐ | アーカイブ/ニュースレター | | 30 | |
| ☑ | アーカイブ/通知 | 7 | 7 | |
| ☐ | 仕事 | | | |
| ☑ | 旅行 | abc | | 保持日数が無効（対象外） |
| ☐ | 削除したラベル | | | Gmail に存在しない |

| 列 | 編集するのは | 内容 |
|---|---|---|
| `対象` | 利用者 | チェックボックス。チェックした行がアーカイブの対象（明示ルール）になる |
| `ラベル名` | システム | Gmail のラベル名。同期が追記するので編集しない（`2024` や `=SUM(A1)` のような名前も文字列のまま書き込まれる） |
| `保持日数` | 利用者 | 受信トレイに残す日数。正の整数のみ有効。`対象` にチェックがある行でだけ使われる（未チェック行の値は無視され、ログも出ない） |
| `適用日数` | システム | その行のラベルに実際に適用される保持日数（自身の設定、または親ラベルから継承した値）。設定が無いラベル・Gmail に存在しないラベルは空 |
| `状態` | システム | 行の状態（下表）。正常なら空 |

- **明示ルール** — `対象` にチェックがあり、`保持日数` が正の整数の行だけがルールになる。
- **親子ラベルの継承** — 親ラベルの行が明示ルールなら、配下の子孫ラベル（`親/子`・`親/子/孫`）も `対象` が未チェックのまま、最も近い明示ルールの祖先の保持日数でアーカイブ対象になる。未チェックは「明示設定なし」であって**除外ではない**（親を対象にしたまま特定の子だけを外す機能はありません）。子孫の行もチェック＋保持日数を入れると、親からの継承値ではなくその行の設定が優先される。
- **チェックありで保持日数が無効** — 空・数値でない・0 以下・小数の行はルールにならず、実行ログに `ℹ️ [スキップ]` をラベルごとに出して残りの行を処理する（`状態` は「保持日数が無効（対象外）」）。
- **同じラベルの行が複数ある場合** — ラベル名の照合は大文字小文字を区別しない（Gmail と同じ）。明示ルールの条件（チェックあり・保持日数が有効）を満たす行のうち**上の行**の設定を採用し、同じラベルの他の行の `状態` は「重複（別の行の設定を適用）」になる。条件を満たす行が 1 つも無ければ（例: どれも未チェック）、どの行も「重複」にはならない（同期は同じラベルを二重に追記しないので、重複行は手で行を足したときか、旧形式シートに元から重複行があったときにだけ生じる）。
- ラベル名に二重引用符 `"` を含むラベルは Gmail 検索を正しく組めないため、実行ログに `ℹ️ [スキップ]` を出して処理対象外になる。
- `適用日数` と `状態` は同期のたびに全行を計算し直す。`対象` や `保持日数` を編集しても、次の同期（次回の日次実行、または `syncLabels` の手動実行）までは表示が更新されない。

`状態` 列の値:

| 値 | 意味 |
|---|---|
| （空） | 正常（またはラベル名が空の行） |
| `Gmail に存在しない` | その行のラベルが Gmail に無い（削除・改名された）。行は削除されずに残り、ラベルが Gmail に戻ると次の同期で空に戻る |
| `保持日数が無効（対象外）` | `対象` にチェックがあるが保持日数が無効なため、ルールになっていない |
| `重複（別の行の設定を適用）` | 同じラベルの別の行（明示ルールの条件を満たす最も上の行）の設定が適用されている |

> **複数のルールに該当するスレッド**: 1 つのスレッドに複数の対象ラベルが付いている場合（例: フィルタで `A` と `A/B` の両方が付いた）、それぞれのルールで判定され、**最も短い保持日数を満たした時点でアーカイブ**されます。例えば `A`=7 日・`A/B`=30 日なら、そのスレッドは 7 日超でアーカイブされます。長く残したいスレッドには短い保持日数のラベルを付けないか、スターを付けてください。

> 列は 1 行目のヘッダ名（`対象` / `ラベル名` / `保持日数` / `適用日数` / `状態`、完全一致）で識別し、列の順序は問いません。`ラベル名` と `保持日数` の列が無いと構成不備として処理を中止します。`適用日数` と `状態` の列が無ければ同期が右端に追加します。
> 検証用のサンプルは [docs/sample-settings.csv](docs/sample-settings.csv) を参照。

### ラベル一覧の同期

同期は Gmail の全ユーザーラベル（受信トレイ・スター付きなどのシステムラベルは除く）と設定シートを突き合わせ、次だけを行います。

- シートにまだ行が無いラベルを、`対象` 未チェック・`保持日数` 空で**末尾に追記**する（Gmail で新しく作ったラベルや、改名後の新しい名前）。
- `対象` 列にチェックボックスを設定し、全行の `適用日数` と `状態` を書き直す。
- 既存行の `対象`・`ラベル名`・`保持日数` は変更せず、行の削除・並べ替えもしない。Gmail から消えたラベルの行は `状態` に「Gmail に存在しない」と表示するだけ。ラベルを改名した場合は旧名の行が「Gmail に存在しない」になり、新しい名前の行が未チェックで追記されるので、必要なら新しい行にチェックと保持日数を入れ直す。
- Gmail のラベル構成と利用者の編集が変わらなければ、何度同期してもシートの内容は変わらない。

同期の実行タイミング:

- **自動** — 日次実行（`archiveLabeledThreads`）の冒頭で、ルールを読み取る前に毎回同期する。
- **手動** — Apps Script エディタで `syncLabels` を選んで実行すると、アーカイブせずに同期だけを行う。新しいラベルを作った直後にシートへ反映したいときや、初回移行の結果を確認したいときに使う。

同期が完了すると、実行ログに `✅ [同期完了] ラベル一覧を同期しました: 追加 N件 / Gmail に存在しない M件` が出ます。

**同期だけが失敗した場合**、日次実行では `⚠️ [エラー] ラベル一覧の同期に失敗しました。…` をログに出し、その時点のシート内容でアーカイブを最後まで続行したうえで、実行をエラーとして終了します（トリガー実行ならトリガー失敗通知メールが届く）。`syncLabels` の手動実行で失敗した場合は `⚠️ [エラー]` を出して実行が失敗として終了します。

### 旧形式シートからの自動移行

以前の形式（`ラベル名 | 保持日数` の 2 列で、ラベル名を手入力していたシート）は、最初の同期（日次実行または `syncLabels`）で自動的に新形式へ移行されます。手作業での移し替えは不要です。

1. 先頭に `対象` 列を挿入する。ラベル名が空でなく保持日数が正の整数の行はチェックあり、保持日数が無効な行はチェック無し（保持日数の値はそのまま残る）。既存行のラベル名と保持日数は変更しない。
2. 続けて通常の同期を行い、残りの全ユーザーラベルを未チェックで末尾に追記し、`適用日数` と `状態` の列を右端に追加する。

移行の前後でアーカイブ対象のラベルと適用される保持日数は変わりません。移行すると実行ログに `✅ [移行完了] 設定シートを新しい形式に移行しました: 対象にチェック N件` が出ます。移行は `対象` 列が無いときだけ行われ、2 回目以降は行われません。

> 移行前にスプレッドシートのコピー（ファイル → コピーを作成）を取り、デプロイ後に `syncLabels` を 1 回手動実行して結果を確認しておくと安心です。

## セットアップ

### 前提

- Google アカウント（個人 Gmail）
- [clasp](https://github.com/google/clasp) v3（`npx @google/clasp@3`）と Node.js 24（`.node-version` で指定）

### 手順

1. **Apps Script プロジェクトを用意** — Apps Script で新規プロジェクトを作成し（または既存プロジェクトを使い）、URL（`https://script.google.com/.../projects/<scriptId>/edit`）から `scriptId` を控える。
2. **ローカル用プロジェクトファイルを作成** — `.clasp.json` をコピーして `.clasp.json.local` を作り、`scriptId` を実 scriptId に書き換える。
   ```sh
   jq --arg id '<scriptId>' '.scriptId = $id' .clasp.json > .clasp.json.local
   ```
   > リポジトリにコミットされている [.clasp.json](.clasp.json) の `scriptId` は placeholder（`REPLACE_WITH_YOUR_SCRIPT_ID`）で、**書き換えずにそのまま維持します**（自動デプロイでは Secret から注入されます。下記参照）。`.clasp.json.local` は `.gitignore` 済みです。リポジトリ直下で `clasp create` / `clasp clone` を実行すると `.clasp.json` が上書きされるため避けてください。
3. **ソースを反映** — `npx @google/clasp@3 -P .clasp.json.local push` で `src/` を Apps Script へ同期。
4. **Script Property を登録** — Apps Script エディタ → プロジェクトの設定 → スクリプト プロパティ:
   - `CONFIG_SPREADSHEET_ID` = 設定スプレッドシートの ID（**必須**）
   - `CONFIG_SHEET_NAME` = シート名（任意。省略時は `settings`）
5. **日次トリガーを作成** — Apps Script エディタで `setupDailyTrigger` を 1 回実行（既定で毎日 3 時台に実行）。初回実行時に OAuth 同意（Gmail / Spreadsheet / トリガー権限）を承認。
6. **ラベル一覧を同期** — Apps Script エディタで `syncLabels` を 1 回実行し、設定シートに Gmail の全ユーザーラベルが並ぶことを確認（旧形式シートならこのとき新形式へ移行される）。アーカイブしたいラベルの `対象` にチェックを入れ、`保持日数` を入力する。
7. **動作確認** — `archiveLabeledThreads` を手動実行し、実行ログと Gmail の状態、設定シートの `適用日数`・`状態` を確認。

手動での統合検証手順は [docs/manual-verification.md](docs/manual-verification.md) を参照してください。

## 自動デプロイ（GitHub Actions）

`main` への push をトリガーに、テスト通過を条件として GAS へ自動デプロイします（[.github/workflows/deploy.yml](.github/workflows/deploy.yml)）。

- `test` ジョブで `npm test` を実行し、成功時のみ `deploy` ジョブへ進む（`needs: test` ゲート）。
- `deploy` ジョブは Secret から認証情報と scriptId を展開し、`clasp push --force` で `src/` を同期。

必要な GitHub Secrets:

| Secret | 内容 |
|---|---|
| `CLASPRC_JSON` | `clasp login`（v3）で生成された `~/.clasprc.json` の全文（`{"tokens": {"default": {...}}}` 形式） |
| `GAS_SCRIPT_ID` | デプロイ先 GAS プロジェクトの実 scriptId（コミット版 `.clasp.json` の placeholder に注入される） |

セットアップ・運用・トークン失効時の復旧手順は [docs/deploy-setup.md](docs/deploy-setup.md) に詳述しています。

### プロジェクト構成

| パス | 役割 |
|---|---|
| [src/Constants.js](src/Constants.js) | 共有定数（Script Property キー、ヘッダ名、`状態` 列の文言、各種上限、トリガー設定） |
| [src/Config.js](src/Config.js) | 設定シートの読取（新旧両形式）・行の分類とバリデーション・親ラベルの展開（ConfigService） |
| [src/Archiver.js](src/Archiver.js) | ルール単位の対象抽出・権威的判定・バッチアーカイブ（ArchiveService） |
| [src/SheetSync.js](src/SheetSync.js) | 旧形式シートの移行とラベル一覧の同期（同期計画の作成とシートへの書き込み、SheetSyncService） |
| [src/Main.js](src/Main.js) | エントリポイント（`archiveLabeledThreads` / `syncLabels`）・オーケストレーション・トリガー管理 |
| [src/appsscript.json](src/appsscript.json) | GAS マニフェスト（タイムゾーン・ランタイム・OAuth スコープ） |
| [test/](test/) | 各サービスの単体テストと、移行から日次実行までを通した結合テスト（`Integration.test.js`） |

> GAS ランタイムでは `src/*.js` が 1 つのグローバルスコープに連結されるため、各ファイルの top-level 関数はそのままグローバル公開されます。各ファイル末尾の `module.exports` ガードは、Node のテストランナーから `require()` できるようにするためのもので、GAS では評価されません。

### 主な定数（[src/Constants.js](src/Constants.js)）

| 定数 | 既定値 | 意味 |
|---|---|---|
| `MAX_THREADS_PER_RUN` | 300 | 1 回の実行全体で処理するスレッド数の上限 |
| `ARCHIVE_BATCH_SIZE` | 100 | `moveThreadsToArchive` の 1 回あたり件数 |
| `ARCHIVE_SEARCH_LIMIT` | 500 | `GmailApp.search` の 1 回あたり上限（ページサイズ） |
| `ARCHIVE_SCAN_LIMIT_PER_RULE` | 1000 | 1 ルールあたりに走査する候補スレッド数の上限（実行時間対策） |
| `TRIGGER_HOUR` | 3 | 日次トリガーの実行時刻（時） |
| `DEFAULT_SHEET_NAME` | `settings` | シート名未指定時の既定シート名 |
| `SYNC_LOCK_TIMEOUT_MS` | 30000 | ラベル同期で同時実行を防ぐスクリプトロックの待ち時間（ミリ秒） |
